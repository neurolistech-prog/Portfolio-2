Section Infrastructure & Cloud Architecture

L'architecture de mes applications repose sur le principe de la haute disponibilité et de la mise à jour en temps réel. Pour le CMA Dashboard, le choix de Firebase Realtime Database a permis de centraliser l'état de l'application sous la forme d'un unique arbre JSON volumineux, accessible instantanément par les clients connectés via le protocole WebSocket.

Chaque modification de l'état système ou de la configuration réseau déclenche instantanément une propagation asynchrone. L'infrastructure élimine le besoin d'un mécanisme classique de requêtage périodique (polling), ce qui réduit drastiquement la consommation de bande passante et garantit une réactivité inférieure à 50 millisecondes lors de la réception d'alertes de monitoring critiques.

Le déploiement global est automatisé par le biais de pipelines GitHub Actions, qui compilent et déploient les scripts serveurs vers des micro-services isolés et le frontend statique directement sur Cloudflare Workers, assurant ainsi une sécurité maximale en périphérie de réseau (Edge Computing).

firebase-cluster-config.js
const firebase = require('firebase-admin');
const serviceAccount = require('./cma-dashboard-config.json');

firebase.initializeApp({
  credential: firebase.credential.cert(serviceAccount),
  databaseURL: "https://cma-dashboard-default-rtdb.firebaseio.com"
});

const db = firebase.database();
const ref = db.ref("cma/live_telemetry");

// Écoute en temps réel de l'état de l'infrastructure
ref.on("child_changed", (snapshot) => {
  const metric = snapshot.key;
  const data = snapshot.val();
  console.log(`[INFRA] Synchronisation Firebase détectée sur : ${metric} ->`, data);
}, (errorObject) => {
  console.error("[INFRA] Échec de la lecture Firebase : " + errorObject.code);
});

Section Gestion SQL & Persistance Relationnelle

Si le temps réel est géré par Firebase, la persistance analytique à long terme et la structuration des données complexes nécessitent l'utilisation de bases de données relationnelles SQL (PostgreSQL / MySQL). Je conçois des schémas relationnels normalisés pour stocker l'historique d'exploitation et les analyses générées par mes systèmes automatisés.

La maîtrise du langage SQL me permet d'écrire des requêtes optimisées avec des jointures multiples, des agrégations avancées et des filtres précis pour auditer les performances. Cela inclut le partitionnement des tables de logs pour maintenir une vitesse de lecture élevée, même lorsque le volume de données dépasse des dizaines de milliers de lignes d'historique.

L'intégrité référentielle, l'indexation stratégique des clés étrangères et la sécurisation des requêtes contre les failles d'injection SQL constituent les fondations techniques de ma méthodologie de gestion de base de données.

SELECT telemetry_id, device_name, error_level, timestamp
FROM cma_system_logs
WHERE error_level = 'CRITICAL'
  AND timestamp >= NOW() - INTERVAL '24 HOURS'
ORDER BY timestamp DESC;

CREATE INDEX idx_telemetry_crit
ON cma_system_logs (error_level, timestamp);

Sécurité Éthique

Mon intérêt pour la cybersécurité me pousse à appliquer le paradigme du Secure by Design dans chacun de mes déploiements. J'analyse régulièrement la robustesse de mes connexions Firebase et de mes accès SQL pour éliminer toute faille potentielle.

→
Règles de Sécurité Firebase Realtime — Implémentation de clauses d'authentification et de validation strictes au niveau des nœuds JSON pour restreindre les droits d'écriture.
→
Assainissement des Requêtes SQL — Utilisation systématique de requêtes préparées et paramétrées pour bloquer toutes les tentatives d'injections de scripts malveillants.
→
Chiffrement des Canaux — Configuration d'échanges de données exclusivement encapsulés sous protocoles TLS/WSS.
